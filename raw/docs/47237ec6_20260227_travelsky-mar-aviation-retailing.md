### 第一部分

#### **第一章  航空零售化趋势与演进**

民航业，作为上个世纪曾经的信息化领先行业，由于环境条件(高管制、高安全性)、业务条件(高成本、高复杂性)和经济条件(低利润)的多重制约，在进入新世纪以来，一直面临来自新的信息技术(数字化)和新的商业环境变化(零售电商)的双重冲击和挑战。为了帮助全球航空业走出困境，实现经营模式从传统走向现代，IATA 于2022年前后提出MAR (全称是 Modern Airline Retailing)愿景,即现代航空零售，其目的是推动航空公司从简单的位移服务，转型为以客户为中心的转型。

为了让 MAR 从理念变成可落地的实践，作为行业标准化指导组织，IATA 又陆续提出了 MAR 的“三大支柱”和“五个核心业务流程”，以推动沿用数十年的传统机票销售体系的变革，同时，为行业内跨主体的信息交互，提供新的业务标准和实施依据。其中的三大支柱分别是：OneID(数字身份)、NDC Offer(动态报价)、ONE Order(统一订单);五个核心业务流程就是POODF (Product 产品-Offer 报价- Order 订单-Delivery 交付-Finance 财务)。

T2RL 公司(总部位于伦敦的咨询公司)作为民航客运领域影响力较大的专业咨询公司，一直紧跟IATA 的 MAR理念,在此后不久,便提出了 OOSD (Offer报价/ Order 订单/ Settle 结算/ Deliver交付)体系。应该说,OOSD**是对**IATAMAR **愿景的一种解读，而非新定义。与**POODF**侧重于全面和完整的行业覆盖相比，**OOSD**更侧重于让航空公司可以方便的组织采购和实施。**二者的核心理念基本相同，都是以统一订单为单一事实来源，端到端的重构航空公司零售流程，通过模块化架构，提升动态定价和旅客服务能力。

为了推动IATA MAR 计划的实践, 2022年12月, IATA启动了航空零售联盟(Airline Retailing Consortium, ARC),该联盟由全球头部航空公司组成，目的是加速全行业100%Offer/ Order 转型,替代 PNR/ET/EMD 旧体系。首批核心成员为：美航、法航、荷航、英航、阿联酋航空、芬航、伊比利亚航空、汉莎、阿曼航空、新航、厦航等，厦门航空(MF)是IATA航空零售联盟的创始成员，也是唯一的中国大陆航空公司成员。

航空销售联盟成立后，主要完成了以下工作：

- 推进 NDC/ONE Order 标准落地与互操作性测试
- 定义 Offer/ Order/ Settle/ Deliver 全链路业务规则
- 输出零售转型路线图、实施指南、最佳实践

这些工作，逐步将 MAR 的理念，在航空业零售联盟各航空公司内形成共识，随后经IATA 旅客服务会议(PSC)及架构与技术战略委员会(ATSB)审议完善，最终，在2023年11月8日在日内瓦召开的IATA 旅客服务会议(PSC)正式通过,以推荐标准(Recommended Practice)- RP1786a的形式发布，作为现代航空零售的官方推荐业务架构标准，RP1786a**也是行业公认的POODF和OOSD的源头。**

至此，我们可以用以下四句话，对本章的内容做个总结：

**MAR，是指导行业发展的新战略。**

**POODF/OOSD，是确保战略执行的新业务流程。**

**RP1786a，是记录战略和执行标准的官方文档。**

**ONE ID+NDC+ONE Order,是实现新业务流程的三大技术支柱。**

#### 第二章 航空零售化的源头-RP1786a详解

RP1786a是IATA发布的基于Offer与Order的推荐标准,其本质是一套纲领性参考框架，用于指导航空公司向MAR转型。

在 RP1786a中，IATA 将航空零售能力拆解为三个支柱：业务(Business)、信息(Information)和技术(Technology),,四个层级: Contextual、 Conceptual、 Logical、 Physical。POODF位于 RP1786a 所定义的参考业务架构层(Business Pillar,Contextual Layer) ,用于描述现代航空零售的业务能力, 是RP1786a 推荐采用的一种业务架构，POODF的行业业务流程参考下图：

![image-20260412231858879](/home/jiaolei/.config/Typora/typora-user-images/image-20260412231858879.png)

在RP1786a行业推荐标准中, IATA主要以POODF流程描述现代航空零售的端到端业务能力框架，这个框架，由以下五部分组成：

Product(产品)：可销售的服务(机票、行李、餐食、贵宾室等)。

Offer(报价)：基于客户请求生成的动态、个性化报价(NDC 核心)。

Order(订单) : 客户确认后生成的 ONE Order,承载所有服务。

Delivery(交付) : 履约(值机、登机、行李、 ancillary 服务等) 。

Finance(财务): 结算、支付、退款、对账等。在RP1786a的文件中,并未直接使用OOSD这一缩写。

#### **第三章  深度剖析** POODF **与**OOSD

 **3.1 POODF 与OOSD 的对比**

IATA 官方对现代航空零售的阐述，主要是MAR 愿景和RP1786a 推荐业务架构标准,RP1786a标准以POODF 描述端到端业务能力，是目前IATA 唯一正式发布的现代航空零售参考架构。OOSD 是由T2RL 咨询公司提出，作为一种更易理解和传播的体系，在行业内迅速普及，也得到了IATA 的认可。例如,在 2025年11月 IATA WPS 会议上, IATA 也将OOSD 作为缩写,并将其与RP1786a架构图中的 Product、Offer、 Order、 Delivery、 Finance  能力模块进行对应说明

![image-20260412232151790](/home/jiaolei/.config/Typora/typora-user-images/image-20260412232151790.png)

OOSD 与POODF 相比, OOSD 更像是一个工程化的方法论,去掉了 Product,用 Settle(结算)替代了宽泛的 Finance(财务)，更聚焦于所有航空公司在实际工作中，使用频率更高的具体的四个核心环节。

从 IATA 视角看，POODF定义在前，是标准化、全行业普适的推荐业务架构；OOSD 在后，是对该架构的简化表达和行业传播用语。

| 对比维度     | POODF                                       | OOSD                             |
| ------------ | ------------------------------------------- | -------------------------------- |
| 源头         | IATA 官方提出                               | T2RL基于IATA标准进行再包装       |
| 时间         | 2022 年RP1786a通过PSC正式确立               | 2022-2023年左右                  |
| 含义         | Product - Offer - Order -Delivery - Finance | Offer - Order - Settle - Deliver |

| 标准         | 是(RP1786a)                                 | 否(非IATA 正式标准)              |
| 颗粒度       | 更细：产品管理(P)与财务结算 (F)             | 更粗：强调核心交易与履约流程     |
| 覆盖范围     | 端到端闭环：产品、交易、履约、结算          | 聚焦交易与服务主流程             |
| 传播方式     | 标准文件、架构蓝图、正式规范                | 厂商白皮书、PPT、招标文件        |

在当前行业实践中，OOSD 与 POODF 承担不同角色：相比 POODF，OOSD 解决了从理念到落地的问题，给出可直接用于系统设计、供应商选型、项目规划的业务模型，易于组织采购和管理，常见于厂商白皮书、研究报告等。而POODF 是IATA 官方推荐的参考业务架构，具有明确的业务边界和能力划分，更适合作为系统规划和工程实施的对标框架。可以将二者理解为：OOSD 是“实践化、易理解”的表达，POODF 是该理念的“标准化、普适化”版本。

总结以上内容，我们的建议如下：

在研讨航信系统演进时，兼顾两者的特点，不是做简单取舍：对外标准对齐和系统设计层面应以IATA 的POODF为主要参考框架，确保与国际标准和主流厂商一致；内部认知统一和方向讨论层面可继续借助OOSD 这一行业简化表达，帮助业务和技术团队，快速理解“以订单为核心”的转型方向，提高沟通和实施效率。

**3.2 POODF 与OOSD 的差异**

在理解 POODF 与OOSD 的同源的基础上，我们也应该看到，由于提出的主体不同(行业组织和咨询公司)，OOSD与 POODF 在技术架构、业务流程、财务结算、生态兼容性、实施成本等方面，依然存在一些差异。

**3.2.1 技术架构**

**模块划分：** 两者均强调将传统单体 PSS拆分为模块化架构,但划分上略有不同。OOSD 包括 Offer(报价)、 Order(订单) 、 Settle(结算) 、 Deliver(交付)四大核心模块;POODF 在此基础上增加了 Product(产品)和 Finance(财务)模块。因此，POODF 更强调前端产品管理和后端财务会计的独立性，把所有可售资源都视为可配置产品，并将收入核算作为独立环节强化。总体来说，两种架构都通过“解耦+模块化”重构航空公司系统，但POODF 的模块颗粒度更细，覆盖范围更广。

**过渡集成：** OOSD 和 POODF 都预见了传统 PSS 向新架构的平滑过渡需求，但重点略有不同。OOSD 强调转型为长期渐进过程，新旧系统并行兼容，关键是实现订单与 PNR/票证的互通转换。IATA 参考架构也设计了过渡形态，如定义 ONE Order (合并订单)作为桥梁,通过保留 PNR 号与Order ID 关联,实现 Legacy PSS 与新订单系统的衔接。因此,两种框架都支持混合架构共存一段时期，通过“翻译层”或中台集成逐步迁移业务。

**3.2.2** **业务流程**

**报价生成**(Offer): OOSD 与 POODF 在报价阶段都强调动态、个性化定价，替代固定舱位等级和票价规则的模式。在 OOSD 架构中, OMS (Offer & Order 管理系统)根据旅客身份、渠道、行程目的等上下文实时生成报价，具备情境感知和连续定价能力。POODF 对 Offer 阶段描述一致,并进一步强调AI驱动的实时报价编排(Offer Orchestration)。两种架构下，航空公司角色均从被动提供票价转变为主动设计个性化旅行方案的“零售商”，实现千人千面的动态零售。

**订单管理(Order)：**订单阶段是两种架构的核心，均围绕 IATA 的“One Order”愿景展开。在传统模式下,旅客预订记录(PNR)与机票票号、EMD 各自存储，改动时需要逐一调整，耗时且易错。OOSD 架构通过 OMS 生成统一订单记录，将行程、支付、服务权益全部关联在一个 Order ID下，订单采用事件溯源方式记录所有变更。POODF 同样将订单视为 Product、 Offer、 Delivery、 Finance 的核心骨架,要求打破信息孤岛并整合全维度信息。不论 OOSD 还是POODF，订单创建后旅客所购航班及附加产品的状态变化都统一更新在订单上，各种业务基于同一订单协同作业，从而大幅提升流程完整性和效率。

**服务交付(Delivery):**在交付环节, OOSD 和 POODF都追求无纸化、无票化履约，但侧重点略有不同。OOSD 强调通过统一订单打破机场执行壁垒，实现持续销售能力和无票出行：OMS 始终保持对订单的控制，登机口前仍可推送升舱服务；旅客通过生物识别等方式凭身份与后台 Order ID 关联，无需传统登机牌。POODF 在交付环节与OOSD 异曲同工：值机/登机时离港系统查询订单验证旅客权益，旅客使用休息室、行李额等权益时即时更新订单并同步财务系统；其交付范围扩展到全旅程，包括酒店、地面接驳等第三方服务履约。总之，两种架构都实现了由静态票证核验向动态订单权益验证的转变，显著优化旅客体验和运营效率。

**3.2.3 财务结算**

在财务清算方面，OOSD 和 POODF 都力图提高实时性和准确性，但POODF更全面地涵盖了财务会计维度。OOSD的 Settle模块核心是基于订单数据进行实时清算，消除传统BSP 模式下的账期长和ADM纠纷。POODF 的 Finance模块则被定义为“价值收尾”，将航空公司财务处理由事后审计转为事中控制。Finance模块细分为订单会计、合作伙伴会计和总账会计三部分，引入实时验证、联运自结算和按订单服务项目自动确认收入等机制。此外，IATA 推出了 SwO(Settlement with Orders)框架,以订单级流程替代传统拆分清算。总体而言， POODF在**财务机制上对**OOSD **进行了扩**展：从关注交易清算拓展为覆盖财务会计、收入管理和结算基础设施升级的全方位改造。这要求航空公司财务系统与订单系统高度集成，实现业财一体化，实时驱动利润和收入核算。对结算合作方而言，新架构需要投入建设自动化对账、订单级结算等能力。虽然两者都倡导“订单即结算”，但POODF 对财务颗粒度和控制的要求更高，需要IT 系统支持更复杂的实时会计规则。

**3.2.4** **生态兼容性**

模块化架构使OOSD 和 POODF 都易于对接外部生态。在OOSD 架构下，统一订单作为全旅程整合载体，航空公司可将酒店、租车等第三方服务组合到订单中，转型为“一站式旅行零售商”。POODF 在 Product 模块中明确支持全品类服务定义，通过统一产品目录将座位、行李、酒店券等元素标准化，并在交付环节跟踪第三方服务的履约状态。两种框架都通过开放接口和标准数据模型，使航空公司IT 系统能够像 OTA一样集成多种旅行产品。

**3.2.5** **实施成本与难度**

无论 OOSD 还是 POODF，都被视为长期的渐进式转型而非一蹴而就的项目。实践中，转型路径包括一次性切换、平行系统或中间转换层等方案，各有利弊。有报告显示，OOSD 稳态成本较传统 PSS低约 12%，全服务航空公司人均登机成本可从1.277美元降至 1.115美元，头部航空公司年节省约400万美元；实施成本比传统 PSS迁移高50%(大型航空公司人均1.5-2美元)，并可能在多年内承担“双轨并行”费用(全复制模式下可能10年以上维护两套系统)。

POODF和OOSD，对应航信现有业务，主要是三个部分：股份公司的PSS+股份公司的航空IT+股份公司下属结算公司的航空结算。应该指出的是，当前，不管是POODF还是 OOSD，都远没有达到稳定状态，都还处在行业引入的早期而非成熟期，其内容和标准，都在随着行业实践的发展，不断丰富、完善、甚至调整。我们应加强与提出和定义这些概念的组织的联系，尤其是加强与IATA和T2RL公司的协作，积极参与其组织的活动，密切双方合作项目和交流交往，才能确保在不断变化的行业发展中不掉队、不落伍、不迷茫。

综上，依托IATA的POODF业务参考架构设计新系统，可充分利用其国际标准背书和经验沉淀，降低探索风险；同时融入 OOSD 理念，可在具体实施时保持灵活性。中国航信可以POODF的“五大模块”为基础设计新一代系统，同时在对外宣传和推广时，用“OOSD”概念阐述转型路径，让各方能够快速形成共识。

### **第二部分** 

#### **第四章全球民航PSS供应商应对零售化现状**

旅客服务系统(PSS)是全球航空公司商务及服务工作的核心业务平台。登机旅客量(PB)是PSS核心服务的计费单位，也是衡量航空技术市场规模的基础指标之一。根据T2RL 公司的统计数据，截至2024年上半年，按PB 量及变化率排名的前三大 PSS 供应商 Amadeus, Sabre 和 TravelSky。

三大PSS供应商的服务模式，都是高度集成的中央系统，其特点是以高度标准化的库存、预订、票务与离港控制为核心，采取集中化部署、社区化服务的运营方式；同时，支持航空公司以 PSS系统为基础，构建收益管理、电商、常旅客等企业级信息系统，通过IATA 标准或厂商自定义标准接口进行交互。在 IATA 推动的航空零售化转型的背景下，PSS作为高可靠的信息基础设施，在未来转型过程中，是不可或缺的重要环节。

与当前的高度集成模式不同，OOSD 架构由大量能力模块共同构成航空公司商业环境，约60项能力，实际可归并为若干可独立采购的功能单元，这些功能单元，最终都体现在T2RL公司为航空公司组织的PSS组件招标流程中。这些单元均非传统 PSS式中央系统，因此航空公司可选择来自多厂商(包括内部IT部门)的OOSD方案。

#### **第五章中国航信**PSS**产品应对零售化不足**

中国航信PSS产品范围包括运价、航班、库存、销售、值机、登机、配载等核心组件。

T2RL在为中国航信提供的咨询报告中指出，按照国际市场标准PSS产品范围，中国航信PSS系统得分为71%，较国际市场供应商平均分(76%)低5%，较国际供应商中位数低11%，较最高分低16%。**尽管中国航信**PSS**产品已针对中国市场深度适配，但以国际市场**PSS**范围进行对标，其得分低于国际供应商的平均值与中位数。**

得分差距产生的主要原因，也就是中国航信PSS产品的缺陷，主要来自以下五个方面，其中三个属于能力缺失，两个属于能力不足：

**1)PSS NDC API 能力缺失**

NDC API目前作为电子商务能力提供。这是NDC能力初期建设路径的自然结果，但如今 NDC集成与外部分发已被视为PSS的核心IT能力，中国航信应重新审视这一架构方式。

T2RL建议，中国航信应该将PSS NDC API分发能力(区别于GDS NDC接收能力)作为 PSS分销渠道能力的一部分提供。随着航空公司通过NDC推出更多真正动态的产品报价，这一点将愈发重要。必须将NDC视为动态产品零售整体演进的一部分，而非孤立目标。

**2)消费者与忠诚度档案功能缺失**

中国航信面临的一个核心问题是，大量与PSS紧密关联的关键组件，正由其航空公司客户自主开发，未与中国航信沟通或引入中国航信参与。这将降低中国航信在航空公司内部的业务覆盖度，为竞争方案提供切入点，进而可能进一步稀释中国航信的潜在收入与客户影响力。

需特别说明的是，这并非一项独立的常旅客忠诚度系统功能，而是如何将客户信息(包括个人和公司客户信息)，与PSS系统已有的预订、出票、支付等功能深度整合。其核心目的是能够访问自有及合作伙伴(包括航空公司、企业客户等)的常旅客档案，从而验证常旅客会员身份，并根据档案信息进行报价、销售、更新预订记录PNR。

**3)单一订单(One Order)规划缺失**

尽管中国航信的航空公司客户目前可能尚未开始规划向 OOSD 过渡，但假以时日，其主要的航空联盟及联运合作伙伴将启动相关规划，并将针对自身的联盟、合资、联运及代码共享协议制定过渡计划，届时中国航信将面临巨大的转型压力。

PSS服务相关需求很可能同样构成未来向现代航空零售转型的需求。在未来设计与架构考量中同时兼顾当前与未来需求，可使新能力同时适配传统PSS生态与OOSD未来生态，避免重复工作，助力中国航信更快实现OOSD 就绪。因此，中国航信应及早开展有关规划工作，能够让现有和潜在客户放心，证明中国航信已有初步的规划安排。

**4)业务规则和流程自动化能力不足**

T2RL 的对标报告指出，在 PSS 系统的业务规则/流程自动化方面，中国航信有24%的相关能力低于市场平均水平。航空公司可配置业务规则的自动化得分，低于平均水平的重点领域，包括以下十个方面：

- 航班计划变更旅客通知
- 动态航班选择/联程构建
- 可用性与销售控制
- 始发-目的地可用性与航段绑定控制
- 候补名单管理
- 团体管理
- 旅客信息收集
- 队列管理
- 豁免规则创建
- 部分离港控制系统(DCS)功能

**5)客户服务能力不足**

从与中国航信团队的沟通来看，航空公司客户与中国航信之间的沟通可更加清晰、更聚焦目标，以便充分理解航空公司需求，并引导其尽可能利用现有方案能力实现目标。

T2RL建议，中国航信应尽可能在航空公司客户现场派驻专职客户团队，聚焦航空公司客户成功，担任产品部署与配置顾问，推动其他方案与中国航信服务的最优集成。完善客服体系，打造卓越客户体验标杆。力争在航空公司寻求解决方案时成为第一对接方，而不是仅在需要集成时才被动介入。

此类客户成功与销售工程团队应从多方面影响客户，其中两项关键职责有助于形成合理、可控的客户预期：

学会何时以及如何说“可以”——倾听并理解航空公司的商业目标，而非其自认为可行的实现方式，利用现有合同服务实现商业目标，而非为定制化需求新建能力。

学会何时以及如何说“抱歉”——在倾听、理解并提供替代方案后，若客户仍不接受，且所提需求将过度占用公共资源、或需产生大量非标代码长期维护，中国航信架构师与客户团队应有信心明确拒绝。

### **第六章中国航信** PSS**产品零售化发展建议** 

PSS 系统作为全球民航业信息基础设施的重要组成部分，一直都占据了民航IT 投资的很大比重。T2RL 公司的研究报告，将全球民航市场IT 投资，分为三个领域：

1)传统技术平台再造

2)支持IATA MAR 愿景的零售应用架构升级

3)人工智能与机器学习技术引入 

**6.1传统技术平台再造** 

所有业务量巨大的 PSS/GDS 企业(例如 Amadeus、 Sabre、中国航信)，在创建初期均采用专有大型机技术，其平台再造启动时间远早于IATA 的新分销能力(NDC)与报价-订单-结算-交付(OOSD)计划。对于大型 PSS/GDS供应商而言，平台再造是一项高度复杂工程，尤其在航空业，高交易量、系统可靠性与安全性是核心考量。

平台业务是各大 PSS企业的“第一曲线”，通过平台再造，实现开放系统技术成功落地后，头部 PSS/GDS 企业将获得以下收益：

**1)战略性收益**

- 提升利用现代技术与新进入者竞争的能力
- 增强支撑数字化转型项目的能力
- 更好地与行业标准与协议对齐
- 对熟悉开放系统的年轻技术人才更具吸引力
- 更强的新兴技术(云、AI等)利用能力

**2)商业收益**

- 相比大型机架构，硬件与维护成本更低
- 减少软硬件供应商锁定
- 新产品与新功能上市速度更快
- 可提供更具竞争力的定价模式
- 更利于提供基于云的解决方案

**3)技术收益**

- 系统架构与部署灵活性更高
- 更易与现代技术及第三方系统集成
- 可扩展性更强，支撑交易量持续增长
- 降低对专业大型机技能人才的依赖
- 更易实施现代开发模式

Amadeus于2017年12月完成开放系统迁移，目前正与微软合作将应用迁移至 Azure云，目标2025年12月完成。Sabre平台再造持续推进，包括将已开放系统的组件上云，合作伙伴为谷歌，目标2025年12月完成上云。与之对应的，中国航信正在通过“213工程”项目以安全为基，聚焦核心技术攻关，进行平台再造。

值得注意的是， Amadeus与 Sabre均借助平台再造契机，不仅将现有应用迁移至新技术环境，同时升级/改造/重写产品组合，利用新技术环境推出全新功能，吸引客户迁移，即用户收益与新技术环境直接挂钩。中国航信也应该考虑同步进行“产品优化”的升级/改造/重写产品，通过功能重构加快去主机进程，坚持科技自立自强塑造新优势，实现“第一曲线”主业焕新。主业焕新是转型的核心路径。要聚焦技术创新、流程优化与模式变革三大方向，着力推动传统核心业务的转型升级。重点在核心系统去主机化进程中同步将新一代信息技术融入其中，全面推进传统客运业务向数字化、智能化与绿色化深度演进，坚决打破路径依赖。推动业务体系从信息化生态链接网络向数字化生态链接网络跃迁，显著提升业务的市场适配性与核心竞争力，让传统主业焕发新活力。利用新技术环境推出全新功能，在开放系统迁移过程中同步实施产品改进与新功能，以持续维系航空公司客户合作。 

根据T2RL的建议，中国航信可考虑在系统改造的同时，针对能力的缺失或不足(内容见第五章)，在如下方向上进行有针对性的重构：

| 序号 | 方向               | 建议                                                         |
| ---- | ------------------ | ------------------------------------------------------------ |
| 1    | PSS NDC 能力       | 将 PSS NDC API 纳入 PSS 能力体系                             |
| 2    | 消费者与忠诚度档案 | 补齐与国际市场PSS 系统标准范围的差距                         |
| 3    | ONE ORDER 规划     | 同步开展面向未来 ONE ORDER 的体系规划                        |
| 4    | 丰富业务规则       | 将由航空公司管理规则触发与配置的业务流程自动化，纳入解决方案设计决策的核心环节 |
| 5    | 客户服务队伍补充   | 现场派驻专职客户团队，聚焦航司客户成功                       |

**6.2 支持 IATA MAR 愿景的零售应用架构改造**

在零售化比较充分的航空公司(尤其是低成本LCC 航空公司中)，PNR、客票、舱位、备案票价等结构正逐步被基于报价与订单理念的系统替代。变革动机之一是让航空业与其他零售行业接轨。国际主流航空技术厂商已相继发布基于报价与订单的系统方案。行业整体转型仍处于极早期，对绝大多数航空公司而言，实际业务尚未发生明显变化。

IATA 定义的 MAR 愿景的重要设计原则之一是：系统将比现有 PSS 更加模块化。由于在多模块协同交互的架构下，很难清晰定义“核心”与“非核心”组件边界，因此，不同企业应根据自身经营需要，确定哪些组件，将作为本企业的“核心”组件。中国航信应尽快确定本企业的“核心”组件，**若中国航信坚持为中国航空公司客户提供核心技术唯一来源的定位，则必须在合理时间内具备这些组件能力。**

T2RL 建议，中国航信可考虑投资建设高性能数据/分析枢纽，作为PSS平台战略的一部分，配备结构化业务数据集市、分析工具接入能力与实时事件驱动的业务自动化能力，打造融合创新生态，实现以数据驱动决策、流程自动升级和用户体验精准优化，构建起数字化发展的新优势。加快建设“AI+航旅”生态与数据应用体系，推动 AI 技术与航旅产业深度融合，研发契合行业需求的智能解决方案，持续提升运营效率、服务品质与客户体验。围绕民航核心业务探索自有数据应用，构建支撑企业迈向“第二曲线”的关键底座，以及业务发展的动力来源和“燃料”，赋能民航业高质量发展。

**6.3人工智能与机器学习**

T2RL 将机器学习定义为：通过对历史行为、操作及现有数据状态/场景的自动外推，形成未来行为或操作假设，从而指导或调整系统行为的任何机制。

航空公司越来越依赖准确、及时的数据支撑收益管理与业务战略，中国航信必须对所有数据相关能力给出积极应答。动态定价引擎的运行完全依赖大量多样化数据。T2RL 建议，在最低限度上，中国航信应将与PSS数据和事件相关的数据及分析能力，整合进PSS产品体系，可选择纳入平台费用或单独计费。

优秀的数据枢纽还可支持事件驱动的运行恢复、旅客消息通知、与服务提供方协同。

T2RL 建议，中国航信可重点围绕以下方向深化人工智能创新应用：

1)产品化与零售：基于消费者购买行为外推，调整服务选项与定价

2)动态可用性与定价/持续价格优化：基于历史行为、竞争情报与订单节奏预测未来价格与支付意愿

### **第三部分** 

#### **第七章中国航信应对航空零售化转型的组合策略**

中国航信向航空公司提供的服务，分为两个模式，一个是多航空公司共用、集中部署、社区化服务的PSS平台服务(关键信息基础设施)，一个是单航空公司部署的、产品化服务的航空IT (以电商为主)。

IATA 新零售理念，对中国航信向其主要客户(国内航空公司)提供的的上述两类服务，都产生了巨大影响，但是，具体的影响，是有区别的：

**7.1 对** PSS **业务的影响-挑战大于机遇**

传统的共用服务平台PSS业务的价值，主要体现在三个方面：

通过整合，把原本分散在不同主体、不同行业、不同流程中的外部服务，内化为 PSS 的系统能力。

通过平台化服务，形成规模效应，摊薄单个用户的使用成本。

通过保持高可靠的运维，让使用PSS的客户，满足民航业高安全监管的要求，满足可持续经营的需求。

通过社区化的服务，选择用户的最佳实践，作为平台功能的实现模板，再推广给其他用户，从而最大限度平摊成本，利用软件复用边际成本低的优势，取得必要的经营利润。

新零售理念(无论是POODF还是OOSD)，本质是相同的，都是把原来一个平台(PSS)内部，经过几十年的积累，高度内聚的能力(订座+离港+分销)拆开，变成可插拔、可替换的松耦合模块(O-O-S-D)。这样的结果，会显著降低该领域的行业进入门槛，有利于新的行业进入者(例如FLYR公司)，对于传统的PSS供应商而言(例如 AMADEUS和中国航信)，将面临直接的挑战。这些挑战，来自以下几个方面：

**竞争加剧:**原本属于 PSS的 Offer、 Order等能力一旦模块化，就很容易被新的专业厂商，以单独招标的方式，形成单点突破。

**整体价值被削弱：**航空公司用拼装思维而不是整包思维来选系统，整合的吸引力下降，价值依然存在，但在决策中的占比下降。

**商业价值下降，保障价值更加突出：**商业决策权前移，决策能力掌握在航空公司属性更强的系统中，PSS 系统作为行业共用平台，价值进一步下沉，逐步成为根据决策系统的指挥，完成海量查询、交易与高频次执行的基础保障系统，商业价值进一步下降，保障作用成为未来PSS系统的主要功能和定位。

为应对零售化的挑战，保持PSS服务的国家关键信息基础设施的地位、市场主导地位不动摇，中国航信应尽快确定在新零售体系下，PSS服务的“核心”组件和“非核心组件”各自有哪些，以及组合方式，并在合理时间内，尽快具备这些组件，尤其是核心组件的服务能力。在技术浪潮中下好“先手棋”，主动拥抱创新重塑竞争优势，阻止竞争对手的进入和侵蚀。

**7.2对航空 IT产品的影响-机遇大于挑战**

新零售理念推动航空业从“运力销售”向“以客户为中心的出行零售”转型，其模块化、松耦合的核心逻辑与航空IT产品的灵活、客户化等特点高度适配、高度契合，为公司航空IT产品(包括结算产品)带来新的发展机遇。这些机遇，体现在以下几个方面：

市场需求扩容：新零售要求航空公司具备动态报价、单一订单管理、全旅程服务整合能力。航空公司对电商化零售平台、个性化营销系统、辅营服务管理、直客结算等航空IT产品的需求呈爆发式增长，且需求从“通用型”转向“定制化、场景化”。

产品价值提升：航空IT产品成为航空公司落地商业决策的核心载体，承接PSS前移的商业决策权，可直接赋能航空公司实现“全旅程产品打包”，从传统的工具型产品升级为航空公司的收益增长型产品。

技术迭代契机：新零售的IATA NDC 标准化接口要求，倒逼航空IT产品完成模块化重构、数据模型升级，推动产品从封闭系统向开放、可插拔的生态化产品转型，适配航空公司“拼装式”系统建设需求。同时，航空IT产品也面临行业标准适配(需严格遵循NDC数据接口与流程规范)、跨系统数据协同(与PSS及第三方模块实现

Offer-Order-Settle-Deliver 全链路数据一致)的双重挑战,对产品的兼容性、数据处理能力提出更高要求。

(关于航空IT产品的应对策略，详见结算公司、航空数字化产品部的研究报告。)

**7.3整体应对策略建议**

中国航信航空公司的核心价值不只体现在单一的PSS业务上，更在于航旅综合服务能力，航空服务产品亟需实现从传统的单点思维到系统思维的转变。以此为指导，构建“PSS+航空IT”业务协同体系，通过系统化的顶层设计实现各板块能力的有机互补。

对于中国航信而言，为进一步巩固公司在国内乃至全球航空IT领域的竞争优势与行业地位，应紧跟航空零售转型(MAR)的整体战略愿景，兼顾国际标准与本土需求、统一规划、渐进实施，聚焦核心能力培养和生态体系重构，确保在新的变革和价值重构中，公司能继续保持在行业中的主导地位不被动摇、提供行业必要支撑的价值不可或缺；帮助“股东+客户”有效控制和降低转型过程中的风险，最终实现从“卖座位”到“卖旅行”的商业模式飞跃。

以PSS平台的高可靠能力、行业规则数据为基础，为航空IT产品提供数据底座与规则支撑；航空IT 产品承接航空，公司的商业营销决策，将报价、订单、辅营销售等数据通过“行业数字化底座”同步至PSS 平台，由PSS保障跨环节的交易一致性。PSS平台将行业监管规则、交易兜底规则推送至航空IT产品，确保产品的个性化创新不突破行业合规与运行安全底线。同时，打通二者的数据链路，实现 “报价—订单—结算—交付”全链路数据实时同步，为航空公司提供从商业决策到交易执行的端到端闭环服务。

这一体系的核心价值，在于把原本分散在不同主体、不同行业、多个流程中的外部服务，通过新的整合，由“PSS+航空IT”能力协同承载，将多主体的外部服务协同，继续内部化为个组织可以持续交付的整体能力，使航空公司只需要面对一个供应商、一个体系，即可获得更低成本、高可靠、可持续的服务。

### **结语**

航空零售化转型已成大势所趋，IATA 已经为这一变革，分别提供了路线图和行业流程，勾画出了航空业以客户为中心、数据实时共享的行业未来业务和技术的发展目标。

零售化转型是大趋势，不是短期行为，航空业是个流程复杂的“巨”系统。我们目前的研究，仅仅涉及庞大内容的冰山一角。下一步，我们将继续按照“国家所需，行业所趋，企业所能”的总体要求，进一步收集资料，根据行业变化和自身实践，不断深化理解，总结经验，并在此基础上，为公司决策提供更多有价值的建议。
